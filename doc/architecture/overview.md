# 点滴タイマー アーキテクチャ設計書

作成日：2026-05-06  
対象アプリ名：点滴タイマー  
対象バージョン：MVP v1.0

---

## 1. アーキテクチャ方針

「点滴タイマー」は、サーバーを持たないフロントエンド完結型のPWAとして構成する。

主な方針は以下である。

- すべての計算処理をスマホ端末内で実行する。
- 外部APIを使用しない。
- 個人情報、計算履歴、入力履歴を保存しない。
- GitHub Pagesに静的ファイルとして配置する。
- Service Workerにより、初回読み込み後は完全オフラインで使えるようにする。
- Reactなどのフレームワークは使わず、HTML / CSS / JavaScriptのみで構成する。

---

## 2. 全体構成

```text
ユーザー
  ↓
スマホブラウザ / ホーム画面PWA
  ↓
app/src/index.html
  ↓
app/src/app.js ── DOM操作・イベント処理・表示更新
  ↓
app/src/calc.js ── 入力検証・丸め・計算
  ↓
app/src/style.css ── スマホ向けUI・ライト/ダークモード
  ↓
app/src/manifest.json ── ホーム画面追加用設定
  ↓
app/src/service-worker.js ── オフラインキャッシュ
```

サーバー側のアプリケーション、データベース、ログ収集基盤は持たない。

## 4. 各ファイルの責務

### 4.1 index.html

画面の骨組みを担当する。

主な責務：

- アプリタイトルの表示
- 残量入力欄の配置
- 終了予定時刻入力欄の配置
- 滴下係数ボタンの配置
- 計算ボタンの配置
- 結果表示エリアの配置
- 条件表示エリアの配置
- エラー表示領域の配置
- CSSとJavaScriptの読み込み
- manifest.jsonの読み込み

---

### 4.2 style.css

見た目とレスポンシブ表示を担当する。

主な責務：

- スマホで見やすい1画面レイアウト
- 入力欄とボタンのサイズ調整
- 結果表示の強調
- 「約○秒に1滴」を最も大きく表示
- 「滴/分」を次に目立たせる
- 「mL/h」を補助情報として表示
- 条件表示を小さく表示
- エラー表示の色・余白・位置調整
- ライトモード / ダークモード自動対応

---

### 4.3 calc.js

計算ロジックを担当する。DOMには直接触らず、固定した `now` を渡して確認できる純粋関数を `window.TentekiCalc` に公開する。

主な責務：

- 残量の入力チェック
- 残量の10mL単位丸め
- 残量の下限・上限チェック
- 滴下係数の検証
- 終了予定時刻の入力チェック
- 終了予定時刻の10分単位丸め
- 現在時刻の秒切り捨て
- 終了予定時刻の当日・翌日判定
- 残り時間の算出
- mL/hの計算
- 滴/分の計算
- 秒/滴の計算
- 表示用テキストと条件テキストの生成

---

### 4.4 app.js

DOM操作とイベント処理を担当する。

主な責務：

- DOM要素の取得
- 滴下係数ボタンの選択状態管理
- 「計算する」ボタン押下イベントの処理
- 現在時刻の取得
- `window.TentekiCalc.calculate()` の呼び出し
- 結果表示
- 条件表示
- エラー表示
- 計算成功後の入力欄リセット

---

### 4.5 manifest.json

PWAとしてホーム画面に追加するための設定を担当する。

主な責務：

- アプリ名の定義
- ホーム画面表示名の定義
- アイコンの指定
- 起動URLの指定
- 表示モードの指定
- テーマ色の指定
- 背景色の指定

設定例の方向性：

```json
{
  "name": "点滴タイマー",
  "short_name": "点滴タイマー",
  "start_url": "./",
  "scope": "./",
  "display": "standalone",
  "icons": [
    {
      "src": "icons/icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    },
    {
      "src": "icons/icon-512.png",
      "sizes": "512x512",
      "type": "image/png"
    }
  ]
}
```

---

### 4.6 service-worker.js

オフライン利用を担当する。

主な責務：

- アプリ本体ファイルのキャッシュ
- 初回読み込み後のオフライン起動
- GitHub Pages上の静的ファイル読み込み
- キャッシュ更新時のバージョン管理

キャッシュ対象：

- `./`
- `./index.html`
- `./style.css`
- `./calc.js`
- `./app.js`
- `./manifest.json`
- `./icons/icon-192.png`
- `./icons/icon-512.png`

## 6. 状態管理

本アプリでは、永続的な状態管理を行わない。

### 6.1 保持する状態

画面表示中のみ、以下の状態をメモリ上に保持する。

- 現在選択中の滴下係数
- 直近の計算結果
- 直近の計算条件
- 入力欄の一時的な値
- エラー表示状態

### 6.2 保持しない状態

以下は保存しない。

- 残量の履歴
- 終了予定時刻の履歴
- 滴下係数の選択履歴
- 計算履歴
- 前回の計算結果
- 患者情報
- メモ

### 6.3 ストレージ方針

以下は使わない。

- localStorage
- sessionStorage
- IndexedDB
- Cookie
- 外部データベース

ただし、Service Workerによるアプリ本体のキャッシュは使用する。これはアプリファイルをオフライン利用するためであり、ユーザー入力値や計算結果を保存する目的ではない。

## 7. 主要ロジック設計

### 7.1 残量処理

```text
入力値取得
  ↓
空欄チェック
  ↓
数値変換
  ↓
10mL単位に四捨五入
  ↓
丸め後の値が10mL以上か確認
  ↓
丸め後の値が2500mL以下か確認
  ↓
計算用残量として使用
```

残量丸めの考え方：

```text
roundedVolume = Math.round(inputVolume / 10) * 10
```

---

### 7.2 終了予定時刻処理

```text
入力時刻取得
  ↓
空欄チェック
  ↓
時・分に分解
  ↓
分を10分単位に四捨五入
  ↓
丸めで60分になった場合は、時を1つ進める
  ↓
24時間を超えた場合は0時に戻す
  ↓
丸め後の時刻で当日・翌日を判定
```

終了予定時刻丸めの考え方：

```text
roundedMinutes = Math.round(minutes / 10) * 10
```

60分になった場合：

```text
08:55 → 09:00
23:55 → 00:00
```

---

### 7.3 当日・翌日判定

現在時刻は、計算ボタンを押した瞬間のスマホ時刻を使用する。秒は切り捨てる。

判定ルール：

```text
丸め後の終了予定時刻 > 現在時刻
  → 今日の終了予定として扱う

丸め後の終了予定時刻 < 現在時刻
  → 翌日の終了予定として扱う

丸め後の終了予定時刻 = 現在時刻
  → 翌日の同時刻として扱う
```

---

### 7.4 計算処理

```text
remainingMinutes = 終了予定日時 - 現在日時
mlPerHourRaw = volumeMl / remainingMinutes * 60
dropsPerMinuteRaw = volumeMl / remainingMinutes * dropFactor
```

表示用のmL/h：

```text
mlPerHourDisplay = Math.round(mlPerHourRaw)
```

ただし、`mlPerHourDisplay` が0で、`mlPerHourRaw` が0より大きい場合は「1mL/h未満」と表示する。

表示用の滴/分：

```text
dropsPerMinuteDisplay = Math.round(dropsPerMinuteRaw)
```

ただし、`dropsPerMinuteDisplay` が0で、`dropsPerMinuteRaw` が0より大きい場合は「1滴/分未満」と表示する。

秒/滴：

```text
secondsPerDrop = Math.round(60 / dropsPerMinuteDisplay)
```

滴/分が「1滴/分未満」の場合は、秒/滴を計算しない。

## 8. エラー処理設計

### 8.1 エラー表示位置

エラーは、該当入力欄の近くに表示する。

```text
現在バッグの残量
[      ] mL
残量を入力してください
```

```text
終了予定時刻
[      ]
終了予定時刻を入力してください
```

### 8.2 エラー発生時の画面状態

すでに計算結果が表示されている状態で次の入力にエラーがあった場合、前回の計算結果は消さない。

新しい計算が成功した場合のみ、結果を上書きする。

- 計算後は結果を大きく表示する。

- 条件は結果の下に小さく表示する。

## 10. オフライン設計

### 10.1 基本方針

Service Workerでアプリ本体をキャッシュし、初回読み込み後は通信なしで利用できるようにする。

### 10.2 キャッシュ戦略

MVPでは、単純なCache First方式を採用する。

```text
リクエスト
  ↓
キャッシュに存在する
  ├─ はい → キャッシュから返す
  └─ いいえ → ネットワークから取得する
```

### 10.3 キャッシュ更新

キャッシュ名にバージョンを含める。

例：

```text
CACHE_NAME = 'tenteki-timer-v1'
```

ファイルを更新した場合は、キャッシュ名を変更して旧キャッシュを削除する。

## 11. デプロイ構成

### 11.1 配置先

GitHub Pagesを使用する。

GitHub Pagesの公開元はリポジトリルートとし、アプリ本体は `app/src/` 配下に配置する。公開URLは `/<repo>/app/src/` とする。

PWAの `start_url` と `scope` は `./` に固定し、GitHub Pages上では `/<repo>/app/src/` ディレクトリ内だけを対象にする。

```text
GitHub Repository
  ↓
GitHub Pages（公開元: リポジトリルート）
  ↓
公開URL: /<repo>/app/src/
  ↓
スマホでアクセス
  ↓
ホーム画面に追加
```

### 11.2 公開範囲

- URLを知っている人はアクセス可能。
- 個人情報を扱わないため、URL公開状態でも運用可能とする。
- ただし、用途は個人の計算補助を前提とする。

## 12. セキュリティ・プライバシー設計

### 12.1 外部通信

外部API通信は行わない。

### 12.2 データ保存

ユーザー入力値、計算結果、履歴は保存しない。

### 12.3 個人情報

患者名、部屋番号、患者IDなどの入力欄は設けない。

利用ログや計算ログは収集しない。

## 13. テスト観点

### 13.1 正常系

- 500mL、終了20:00、20滴/mLで計算できる。
- 15滴/mL、20滴/mL、60滴/mLを切り替えて計算できる。
- 終了予定時刻が翌日の場合に正しく計算できる。
- 終了予定時刻が現在時刻と同じ場合、24時間後として計算できる。
- 計算後に入力欄がリセットされる。
- 計算結果は次の正常計算まで残る。

### 13.2 丸め処理

- 123mL → 120mLとして計算される。
- 125mL → 130mLとして計算される。
- 08:14 → 08:10として計算される。
- 08:15 → 08:20として計算される。
- 23:55 → 00:00として扱える。

### 13.3 エラー系

- 残量空欄でエラーが出る。
- 残量0mLでエラーが出る。
- 残量2505mL入力時、丸め後2510mLとなりエラーが出る。
- 終了予定時刻空欄でエラーが出る。
- エラーが出ても前回結果は残る。

### 13.4 表示系

- 秒/滴、滴/分、mL/hの順で表示される。
- 秒/滴が最も大きく表示される。
- 条件表示が小さく表示される。
- ライトモードで見やすい。
- ダークモードで見やすい。

### 13.5 PWA・オフライン

- GitHub Pages上で表示できる。
- ホーム画面に追加できる。
- 初回読み込み後、オフラインでも表示できる。
- オフラインでも計算できる。

## 14. 将来拡張候補

MVPでは実装しないが、将来的に検討できる機能は以下である。

- よく使う残量プリセット
- よく使う終了予定時刻プリセット
- 1本あたりの時間自動割り振り
- リアルタイムカウントダウン
- 終了予定時刻の通知
- 計算式の表示切り替え
- テーマ手動切り替え
- 本格的なアイコン

ただし、医療用途に近い性質があるため、機能追加時も誤入力・誤認・過信を避ける設計を優先する。
