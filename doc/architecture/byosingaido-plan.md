# 秒針ガイド機能追加計画

## Summary
- 計算成功後だけ、結果パネル下部にアナログ秒針ガイドを表示する。計算前は秒針エリアを表示しない。
- 秒針は端末の現在秒に同期し、1秒ごとに刻む。開始/停止ボタンは作らない。
- ガイドは「計算成功時の時刻」を基準に、`約N秒に1滴` のN秒間隔で動く。現在秒針から次の目印までを色付き範囲で示し、2つ先の目印は破線で控えめに表示する。ただし、読ませる線は3:1以上のコントラストを保つ。
- 計算成功後は結果パネルへ自動スクロールし、主結果、滴/分、mL/h、条件、秒針ガイドが同じ流れで見える位置に移動する。
- 秒針ガイドはカウントダウンタイマーではなく、滴下間隔を目視で合わせるための補助表示として扱う。
- 入力変更後や入力エラー時は、表示中の結果とガイドが「前回の計算結果」であり、新しい入力はまだ反映されていないことを画面上に表示する。

## Implementation Changes
- `window.TentekiCalc.calculate()` の `result` に、ガイド判定用の数値を追加する。既存の `mainText`、`dropsPerMinuteText`、`mlPerHourText`、`secondsPerDropText` は維持する。
- 追加する値は `dropsPerMinuteValue`、`secondsPerDropRaw`、`secondsPerDropSeconds`、`isSecondGuideEligible` とする。
  - `dropsPerMinuteValue` は丸め前の滴/分を数値で返す。
  - `secondsPerDropRaw` は `dropsPerMinuteValue > 0` の場合に `60 / dropsPerMinuteValue` を数値で返し、それ以外は `null` を返す。
  - `secondsPerDropSeconds` は、既存表示と同じく表示用に丸めた滴/分から算出した整数秒を返す。`1滴/分未満` の場合は `null` を返す。
  - `isSecondGuideEligible` は `secondsPerDropRaw >= 1` かつ `secondsPerDropSeconds !== null` かつ `secondsPerDropSeconds < 60` の場合だけ `true` にする。
- アナログガイドを表示する対象は `isSecondGuideEligible === true` の計算結果だけに限定する。`null`、1秒未満相当、60秒以上は盤面を出さず、対象外の補助文だけ表示する。
- ガイドの間隔表示には `secondsPerDropSeconds` を使う。1秒未満の除外判定には `secondsPerDropRaw` または `isSecondGuideEligible` を使い、丸め表示だけで対象可否を決めない。
- `calc.js` にDOM非依存の `getSecondGuideState(anchorMs, intervalSeconds, nowMs)` を追加し、`window.TentekiCalc` から公開する。`app.js` はこの戻り値をSVGへ反映するだけにする。
- `getSecondGuideState()` は、現在秒針角度、次目印角度、2つ先目印角度、現在位置から次目印までの範囲角度、盤面上ラベルを出すかどうかを返す。N秒が60を割り切らない場合も、固定目盛りを並べず、現在時刻に対する次目印と2つ先目印だけを動的に返す。
- `getSecondGuideState()` は `anchorMs` と `nowMs` のミリ秒を内部で秒境界へ切り捨てる。秒針ガイドは1秒刻みの補助表示なので、小数秒の角度は扱わない。
- 次目印は常に現在時刻より後の目印にする。`nowMs === anchorMs` や `nowMs === anchorMs + intervalSeconds * 1000` のように現在位置が目印ちょうどの場合でも、次目印は現在位置ではなく次の未来の目印へ進める。
- submit処理では冒頭で `clickedAt = new Date()` を1回だけ作り、`calculate({ now: clickedAt })` と `anchorMs = Math.floor(clickedAt.getTime() / 1000) * 1000` の両方に使う。計算ボタン押下の同じ時刻を基準にし、ガイド側は秒目盛りへ合わせる目的でミリ秒だけを切り捨てる。
- 計算ロジックは従来どおり分単位で行う。秒針ガイドは計算成功時の `clickedAt` から作った秒境界の `anchorMs` を基準にする視覚補助であり、残り時間や滴下速度の再計算には秒やミリ秒を使わない。
- `app.js` は `guideTimeoutId` と `guideRunId` を持つ。`setInterval` は使わず、次の秒境界に合わせた再帰的 `setTimeout` で更新する。
- 新しい成功計算時は、既存の `guideTimeoutId` を停止し、`guideRunId` を増やしてから新しいガイドを開始する。各更新コールバックは開始時に受け取った `guideRunId` と現在の `guideRunId` を比較し、古い更新なら何もせず終了する。
- 対象外の成功計算時は、既存タイマーを停止して `guideRunId` を増やし、盤面は出さず対象外の補助文を表示する。
- エラー時は既存タイマーを止めず、前回ガイドを残す。ただし、状態表示を「前回の計算結果」に切り替える。新しい条件は、次に計算成功するまでガイドへ反映しない。
- ユーザー操作で入力欄または滴下係数を変更した時点で、前回結果が表示中なら状態表示を「前回の計算結果」に切り替える。計算成功後に `resetInputs()` や `setSelectedDropFactor(DEFAULT_DROP_FACTOR)` で行うプログラム上のリセットは、前回結果化のトリガーにしない。
- 前回結果化は `input` イベント、ユーザー操作による `change`、滴下係数ボタンの `click` だけで行う。実装時は `isResettingAfterSuccess` のような一時フラグ、またはリセット完了後にユーザー操作ハンドラだけを通す構成で、成功直後の通常状態を維持する。
- ガイド更新は初回表示を即時反映し、その後は次の秒境界に合わせて再帰的に更新する。毎秒更新するDOMはSVG属性に限定し、毎秒変わるテキストは作らない。
- Service Workerのキャッシュ名を `tenteki-timer-v2` へ更新する。新しいファイルを追加する場合は `ASSETS` に必ず追加する。
- 外部API、保存API、通知、音、バイブレーション、Wake Lockは追加しない。

## UI and Accessibility
- ガイドは結果パネル内の条件表示の下に配置する。計算前はガイド領域を出さず、計算成功後に安定した余白付きで追加する。
- ガイド領域には固定の状態表示を置く。通常時は「表示中の結果に基づくガイドです。」、入力変更後またはエラー時は「前回の計算結果に基づくガイドです。新しい条件は計算すると反映されます。」と表示する。
- 盤面は正方形のSVGで描き、320px幅でも横スクロールしない固定比率にする。SVG本体は `inline-size: min(100%, 220px)`、`block-size: auto`、`aspect-ratio: 1 / 1`、中央寄せを基本にし、狭い画面では `inline-size: min(100%, 180px)` まで下げる。
- 360x640での受け入れ条件は、計算成功後のスクロール位置で、主結果、滴/分、mL/h、条件、状態表示、ガイド盤面の上半分以上が同じ流れで見えることとする。条件とガイドの間には少なくとも12pxの余白を置く。
- SVG全体は `aria-hidden="true"` と `focusable="false"` を付ける。読み上げ用の説明はSVGではなく、視覚非表示テキストまたは固定の補助文として用意する。結果パネル全体の `aria-live="polite"` 内で毎秒変わるテキストを更新しない。
- ガイド状態文と読み上げ用固定文は、通常、前回結果、対象外のように状態が変わった時だけ更新する。同じ状態のまま入力が続く場合は同じ文を再設定しない。
- 読み上げ用の固定文を用意する。通常時は「秒針ガイドを表示しています。次の目印と2つ先の目印を目安にしてください。」、対象外時は「この計算結果は秒針ガイドの対象外です。」、エラー時は「入力エラーのため、表示中のガイドは前回の計算結果です。」とする。
- 次目印には「次」、2つ先目印には「2つ先」のラベルを付ける。ただし `secondsPerDropSeconds <= 2` の短間隔では盤面上の文字ラベルが重なりやすいため、盤面上ラベルは出さず、盤面外の凡例だけで「実線: 次」「破線: 2つ先」を示す。
- `secondsPerDropSeconds <= 2` の場合、次目印と2つ先目印は盤面外周の短い目盛りとして描く。次目印は実線、2つ先目印は破線に固定し、線幅、長さ、外側凡例の位置をCSSで固定して1秒/2秒ケースを確認する。
- `secondsPerDropSeconds > 2` の場合も、次目印は常に実線、2つ先目印は常に破線にし、色や薄さだけに依存しない。
- 基準目盛りは12時、3時、6時、9時の4点に絞って表示する。細かい秒目盛りは追加せず、次目印と2つ先目印を優先して読めるようにする。
- 色付き範囲は安全・危険を示すものに見えないよう、補助文で「次の目印までの目安」と説明する。ライト/ダーク両方で、目印、秒針、範囲、盤面のコントラストを確認する。
- 色は既存CSS変数に合わせるが、読ませる線には `--line` をそのまま使わない。ガイド専用に `--guide-line`、`--guide-muted-line`、`--guide-range` を追加し、盤面外周、基準目盛り、秒針、次目印、2つ先目印はいずれも背景または盤面面色に対して3:1以上を目安にする。薄い装飾線だけは `--line` を使ってよい。
- 秒針と次目印は `--accent` 系、2つ先目印は3:1以上を満たす `--guide-muted-line` の破線、範囲塗りは `--guide-range` を使う。通常文字は4.5:1以上、大きい文字とUI境界は3:1以上を目安に確認する。
- ガイド近くにも「目安ガイドです。指示・施設ルールに従って確認してください。」を表示する。
- 自動スクロールは計算成功時だけ行う。結果とガイドDOMを描画してから `requestAnimationFrame` 後にスクロールする。スクロール先は主結果の直前に固定し、見出しだけでなく主結果が見える位置にする。エラー時は既存どおり最初の不正入力へフォーカスし、結果パネルへスクロールしない。
- 計算成功時は、入力リセット後に結果パネルへフォーカスを移さない。スクリーンリーダー向けには既存の `aria-live="polite"` で結果更新を伝え、キーボード利用者の現在位置を不用意に奪わない。
- `prefers-reduced-motion` の場合、スムーズスクロールは使わず即時スクロールにする。秒針は1秒ごとの位置更新に留め、点滅や強い強調演出は入れない。

## Test Plan
- `app/tests/calculation-test.html` に `dropsPerMinuteValue`、`secondsPerDropRaw`、`secondsPerDropSeconds`、`isSecondGuideEligible` の確認を追加する。20滴/mLで4秒、15滴/mLで6秒、60滴/mLで1秒を確認する。
- `1滴/分未満` では `secondsPerDropSeconds === null`、`isSecondGuideEligible === false` になることを確認する。
- 高滴下数で表示上は約1秒でも `secondsPerDropRaw < 1` になるケースを作り、`isSecondGuideEligible === false` になることを確認する。
- 60秒以上になる低滴下数では `isSecondGuideEligible === false` になり、アナログガイド対象外にできることを確認する。
- `getSecondGuideState(anchorMs, intervalSeconds, nowMs)` を固定値で確認する。N秒が60を割り切るケース、割り切らないケース、分をまたぐケース、2つ先目印が更新されるケースを含める。
- `getSecondGuideState()` は `anchorMs` と `nowMs` のミリ秒を切り捨てることを固定値で確認する。たとえば `08:00:00.900` を渡しても `08:00:00.000` 基準の角度になることを確認する。
- `getSecondGuideState()` の境界値を確認する。`nowMs === anchorMs`、`nowMs === anchorMs + intervalSeconds * 1000`、分またぎ直後でも、次目印が現在位置ではなく次の未来の目印になることを確認する。
- タイマーライフサイクルをブラウザで確認する。連続して計算成功した場合に古い `setTimeout` 更新が残らないこと、対象外の成功計算で盤面更新が止まること、エラー時に前回ガイドは動き続けるが状態表示が前回結果になることを確認する。
- ブラウザで、計算前はガイド非表示、計算成功後は結果パネルへ自動スクロールし、結果とガイドが見えることを確認する。
- 計算成功後の入力欄リセットでは「前回の計算結果」表示に切り替わらず、ユーザーがその後に入力欄または滴下係数を変更した時だけ「前回の計算結果」表示へ切り替わることを確認する。
- 秒針が端末の現在秒と一致し、1秒刻みで進むことを確認する。
- 入力変更後に前回結果と前回ガイドが残り、「前回の計算結果」であることが表示されることを確認する。
- 入力エラー時に前回結果と前回ガイドが消えず、「前回の計算結果」であることが表示されることを確認する。
- `secondsPerDropSeconds <= 2` では盤面上ラベルを出さず、外側凡例で実線/破線の意味が分かること、1秒/2秒ケースで次目印と2つ先目印を見分けられることを確認する。
- 360x640、390x844、320px幅で、横スクロールせず、主結果、滴/分、mL/h、条件、状態表示、ガイドが読めることを確認する。360x640では自動スクロール後にガイド盤面の上半分以上が見えることを確認する。
- ライト/ダークモードで、盤面外周、基準目盛り、秒針、次目印、2つ先目印、色付き範囲、補助文が読めることを確認する。読ませる線とUI境界は3:1以上、通常文字は4.5:1以上を目安にする。
- 計算成功時に結果パネルへフォーカスが移らず、エラー時に最初の不正入力へフォーカスする既存挙動が保たれることを確認する。
- ガイド状態文と読み上げ用固定文が状態変化時だけ更新され、同じ状態の入力継続で同じ文が再通知されないことを確認する。
- `prefers-reduced-motion` 時に、スムーズスクロールや強い点滅が発生しないことを確認する。
- v1キャッシュ導入済み状態からv2へ更新し、タブまたはPWA再起動後に新UIが表示されることを確認する。
- 初回読み込み後、オフラインでも秒針ガイド付きの画面表示と計算ができることを確認する。

## Assumptions
- 秒針ガイドは医療判断の代替ではなく、既存の注意文言と同じ前提で扱う。
- 数値カウントダウンは出さない。
- 画面維持、音、通知、バイブレーション、Wake Lockは今回の範囲外。
- 滴下速度の計算自体は既存要件どおり分単位で行う。秒針ガイドだけが、目視補助として秒境界に丸めた現在時刻を使う。
- 計算結果、入力値、秒針ガイド状態は永続保存しない。Service WorkerのCache APIはアプリ本体ファイルのオフライン利用に限って使う。
